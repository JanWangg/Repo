## 核心理念

女媧不是複製人，是**提煉思維框架**。

一個好的人物 Skill 是一套可運行的認知作業系統：
- 他用什麼**心智模型**看世界？（鏡片）
- 他用什麼**決策啟發式**做判斷？（直覺規則）
- 他怎麼**表達**？（DNA）
- 他**絕對不會**做什麼？（反模式）
- 什麼是這個 Skill **做不到的**？（誠實邊界）

**關鍵區分**：捕捉的是 HOW they think，不是 WHAT they said。

## 執行流程（5 個 Phase）

### Phase 0：入口分流

| 用戶輸入 | 路徑 | 範例 |
|---------|------|------|
| 明確的人名/主題 | **直接路徑** → Phase 0A | 「蒸餾芒格」「做一個費曼 skill」 |
| 模糊的需求/困惑 | **診斷路徑** → Phase 0B | 「我想提升決策品質」「我需要一個思維顧問」 |

#### Phase 0A：需求澄清（直接路徑）
收到明確名字後，確認：
1. 這個人/主題是誰
2. 聚焦方向（可選）：全面畫像 vs 聚焦某個維度？
3. 用途：思維顧問？決策參考？角色扮演？
4. 新建 or 更新：是否已有該人物的 Skill？
5. 本地語料：用戶手上有沒有一手素材（PDF、transcript）？

#### Phase 0B：需求診斷（模糊路徑）
用 1-2 個提問定位核心需求 → 推薦 2-3 個候選（已有 Skill 優先）→ 用戶選擇後進入 Phase 1。

### Phase 1：多源資訊採集（並行 6 個 Agent）

| Agent | 維度 | 輸出檔案 |
|-------|------|---------|
| 1 著作 | 書、長文、論文、newsletter | `01-writings.md` |
| 2 對話 | 播客、長影片、AMA、深度採訪 | `02-conversations.md` |
| 3 表達 | Twitter/X、微博、即刻、短文 | `03-expression-dna.md` |
| 4 他者 | 他人分析、書評、批評、傳記 | `04-external-views.md` |
| 5 決策 | 重大決策、轉折點、爭議行為 | `05-decisions.md` |
| 6 時間線 | 完整時間線 + **最近 12 個月動態** | `06-timeline.md` |

#### 6 個 Agent 硬性要求
- 調研結果必須寫入對應的 `references/research/0X-xxx.md`
- 標註資訊來源和可信度（一手 > 二手 > 推測）
- 區分「他說過的」vs「別人說他的」vs「我推斷的」
- 發現矛盾時保留矛盾，不要和稀泥

#### 資訊源黑名單（永遠排除）
- **知乎**：洗稿嚴重、資訊失真率高
- **微信公眾號**：封閉生態、無法驗證
- **百度百科/百度知道**：資訊陳舊且不可靠

中文渠道只接受：36氪、極客公園、晚點 LatePost、財新、第一財經、虎嗅、少數派、機器之心

#### 資訊源優先級
- 用戶提供的一手素材（**最高+**）
- 本人著作、長對話/訪談、實際決策記錄（最高）
- 社交媒體（中等）
- 他人評價（中等）
- 二手轉述（低）

### Phase 2：降維與交叉驗證（主 Agent 獨占）

#### 2.1 提取核心心智模型（最重要）
只保留那些同時在「著作/講話」和「實際決策」中都出現的模型。**如果他說一套做一套，以「做」為準**。

提取 3-7 個核心模型，每個必須包含：
- **名稱**（最好是他自己的術語）
- **核心主張**（一句話）
- **觸發條件**（什麼情況下他會用這個模型）
- **失效條件**（什麼情況下這個模型不適用）
- **支撐案例**（至少 1 個真實決策/言論支撐）

#### 2.2 提取反模式（Anti-patterns）
他極度厭惡什麼？他堅決不做什麼？（這通常比他做什麼更能定義一個人）

#### 2.3 提取表達 DNA
- 高頻句式（如「人們通常認為...但我發現...」）
- 比喻偏好（軍事？物理學？生物學？）
- 規避詞彙（他從來不用的詞）

#### 2.4 尋找內在張力（矛盾點）
偉大的思想者都有內在矛盾。提取 1-2 對矛盾點，這會讓生成的 Skill 有「活人味」。

### Phase 3：組裝與指令生成

使用 `references/templates/skill-template.md` 組裝最終的 SKILL.md。

#### 回答工作流（Agentic Protocol）生成指引

**核心原則**：人物 Skill 不憑感覺說話。遇到需要事實支撐的問題時，先做功課再回答。

**3 個 Step**：

```markdown
## 回答工作流（Agentic Protocol）

### Step 1: 問題分類
- 需要事實的問題（具體公司/人物/事件）→ 先研究再回答
- 純框架問題（抽象價值觀、思維方式）→ 直接用心智模型回答
- 混合問題 → 先獲取案例事實，再用框架分析

### Step 2: [人物名]式研究
⚠️ 必須使用工具（WebSearch 等）獲取真實資訊，不可跳過。
（根據此人的心智模型和分析偏好，生成 3-5 個研究維度分類）

### Step 3: [人物名]式回答
基於 Step 2 獲取的事實（如有），運用心智模型和表達 DNA 輸出回答。
```

**Step 2 研究維度推導方法**：
從蒸餾出的心智模型反推此人分析問題時最關注什麼，將其轉化為具體的搜尋維度。

| 人物 | 核心心智模型 | → 推導出的研究維度 |
|------|------------|------------------|
| 芒格 | 多元思維模型、逆向思考、激勵機制 | → 看護城河、看管理層激勵結構、看最大風險（逆向）、看歷史類比 |
| 費曼 | 第一性原理、對權威的懷疑 | → 看基本物理/數學約束、看官方說法的邏輯漏洞、看實驗數據 |
| 塔勒布 | 反脆弱、尾部風險、知識的僭妄 | → 看極端情況、看誰在承擔尾部風險、看專家預測的歷史記錄 |

### Phase 4：品質驗證

用子 agent 執行 3 項測試（獨立於主 agent，避免自評偏差）：

#### 4.1 已知測試（Sanity Check）
選 3 個此人公開表態過的問題，spawn 子 agent 帶著新 Skill 回答，對比實際立場。

#### 4.2 邊緣測試（Edge Case）
選 1 個此人沒公開討論過但相關的問題，用 Skill 推斷。
- 期望結果：「基於模型 X 和 Y 的推斷，可能...但不確定」

#### 4.3 風格測試（Voice Check）
用 Skill 寫一段 100 字分析，判斷：
- 有此人的表達特徵？
- 不是通用 AI 味雞湯？
- 不是原話拼湊？

#### 通過標準

| 檢查項 | 通過標準 | 不通過信號 |
|--------|---------|-----------|
| 心智模型數量 | 3-7 個，每個有來源證據 | <3 個或>10 個，無證據支撐 |
| 每個模型的侷限性 | 明確寫出失效條件 | 只寫優點 |
| 表達 DNA 辨識度 | 讀 100 字能認出是誰 | 像通用 ChatGPT |
| 誠實邊界 | 至少 3 條具體局限 | 只有「不能替代本人」 |
| 內在張力 | 至少 2 對矛盾 | 觀點高度一致（太假） |
| 一手來源占比 | >50% | 主要依賴二手轉述 |

**迭代上限**：Phase 2→4 最多循環 2 次。2 輪後仍有不通過項，交付當前最優版本。

Phase 4 驗證通過後，自動啟動雙 Agent 精煉：

- **Agent A（auto-skill-optimizer 視角）**：8 維度結構評估 + 改進建議

## 特殊場景

### 活人 vs 歷史人物
- **活人**：注意時效性，標註截止日期，建議定期更新
- **歷史人物**：材料更穩定但可能有傳記偏差，多源交叉驗證

### 主題 Skill vs 人物 Skill

| Phase | 人物 Skill | 主題 Skill 變體 |
|-------|----------|----------------|
| 0A | 確認人名+聚焦方向 | 確認主題邊界+目標受眾 |
| 0.5 | `[person]-perspective/` | `[topic]-framework/` |
| 1 | 6 個 Agent 圍繞一個人 | 先搜尋該主題的 3-5 個核心人物/流派 |
| 2.1 | 提取一個人的心智模型 | 提取**領域共識框架**+**各家分歧** |
| 2.3 | 模擬一個人的表達 | 用中性但專業的表達 |

### 中國人物 vs 西方人物
- **中國人物**：B 站原始影片/演講、小宇宙播客、權威媒體採訪
- **西方人物**：Twitter、YouTube、Podcast、Amazon 書評

### 冷門人物（公開資訊極少）
當 Phase 0.5 評估後發現可用來源 <10 條時：
1. 告知用戶「這個人公開資訊很少，Skill 品質會受限」
2. 心智模型減至 2-3 個，標註「基於有限資訊推測」
3. 誠實邊界 section 加大篇幅
4. 鼓勵用戶提供一手素材

### 蒸餾用戶自己
- 女媧無法從公開渠道搜到用戶的思維框架
- 需用戶提供：個人文章/部落格、錄過的影片/播客、寫過的決策備忘錄
- Phase 1 改為分析用戶提供的素材
- 注意「自我認知偏差」——用戶可能高估某些特質、忽略盲點

## 品味守則

| 原則 | 一句話 |
|------|--------|
| 長文 > 金句 | 3000 字 essay 比 50 條推文更揭示思維結構 |
| 爭議 > 共識 | 最被爭議的觀點最能揭示獨特性 |
| 變化 > 固定 | 改變立場的地方比一直堅持的更有資訊量 |

### 絕不做的事
- 編造此人沒說過的話
- 把通用道理包裝成此人的「獨特見解」
- 忽略負面評價和爭議
- 在資訊不足時強行生成

## 本地語料處理

| 素材類型 | 處理方式 | 覆蓋維度 |
|---------|---------|---------|
| 書籍 PDF | 直接閱讀提取核心論點 | 著作(01) |
| 演講/訪談 transcript | 分析問答模式和即興反應 | 對話(02)、表達(03) |
| 影片字幕 SRT | 同 transcript 處理 | 對話(02)、表達(03) |
| 部落格/newsletter | 提取系統性觀點 | 著作(01) |
| 社交媒體匯出 | 分析碎片表達模式 | 表達(03) |
| 內部文件/備忘錄 | 分析決策邏輯 | 決策(05) |

**本地語料的品質優勢**：用戶手上的一手素材（尤其是完整書籍、長訪談原文）通常比網路搜尋到的二手轉述品質高得多。

## 失敗處理

- **單個 Agent 超時**（搜尋 5 分鐘無有價值結果）：不等待，繼續推進。在 Phase 2 中標註「資訊不足」
- **資訊源匱乏**（<10 條高價值來源）：提示用戶「資訊較少，是否繼續或補充本地語料？」
