# 第二章：解決方案總覽

## 2.1 方案名稱

```
【Smart Procurement AI — 採購智能化系統】
簡稱：SPAI
定位：n8n 工作流引擎 + T100 ERP + Domino Mail + AI Agent
覆蓋：RFQ → 核價 → PO → 委外 → IQC → 入庫 → AP
```

## 2.2 系統邊界

```
【覆蓋範圍】
├─ RFQ 詢價與供應商比價（Agent 1）
├─ 核價流程輔助決策（Agent 1/4）
├─ PO 建立、Release、追蹤（Agent 2）
├─ 委外工單追蹤與交期管理（Agent 4）
├─ IQC/FQC 品質檢驗通知（Agent 2/4）
├─ 完工入庫預測（Agent 2/4）
├─ 發票自動化解析與比對（Agent 5）
└─ 應付帳款異常偵測（Agent 5）

【不在範圍】
├─ T100 系統本身改造
├─ Domino 系統改造
├─ 財務会計模組
└─ 人事系統整合
```

## 4.2 T100 API 端點總表（完整版）

```
模組一：aimm214 據點採購資料

模組二：axmt421/axmt420 核價
  GET /api/axmt421/query         ← 歷史核價查詢
  GET /api/axmt421/expiring      ← 核價到期預警

模組三：RFQ / 採購價格
  GET /api/axmt410/query         ← 估價單查詢
  GET /api/aooi084/query         ← 採購價格參照表
  POST /api/aooi084/update       ← 寫入供應商報價

模組四：apmt500 採購單
  GET /api/apmt500/query         ← 讀取 PO 明細
  POST /api/apmt500/create       ← 建立 PO
  POST /api/apmt500/release      ← Release PO
  POST /api/apmt500/update_status← 更新 PO 狀態

模組五：aqct300 IQC/FQC
  GET /api/aqct300/query         ← 讀取 QC 結果
  GET /api/aqct300/urgent        ← 緊急 QC 催辦

模組六：asft300/340/311 入庫發料
  GET /api/asft300/query         ← 讀取委外工單

  POST /api/aapt110/match        ← 寫入發票匹配
```

# 第六章：AI Agent 設計

## 6.1 人類 Gate 設計（四個審核點）

```
Gate 1：非 AVL 候選供應商審核
  └─ AI 搜尋候選供應商 → 人確認後才發 RFQ

Gate 2：比價報告審核
  └─ AI 生成完整比價報告 → 人核准後才建 PO

Gate 3：交期異動處理審核
  └─ AI 發現延誤 > 2 天 → 人選擇行動

Gate 4：發票異常審核
  └─ AI 發現 🔴 紅燈 → AP 主管親自處理
```

# 第八章：開發時程與里程碑

## 8.1 三階段開發規劃

```
【Phase 1：Pilot（4-6 週）】
目標：1 個據點（松江）、1 個採購員
範圍：RFQ 比價 + PO 追蹤 + Email 解析
成功指標：RFQ 比價報告生成、PO 追蹤覆蓋率 > 80%

第 1-2 週：環境建置（T100 API + Domino IMAP + n8n）
第 3-4 週：Workflow 建立（Agent 0-3）
第 5-6 週：Pilot 上線 + 觀察調整

【Phase 2：委外系統（6-8 週）】
目標：四個據點全覆蓋
範圍：Agent 4（委外管理）+ 委外 OTD 追蹤
成功指標：委外 OTD 從 56% 提升至 65%

第 7-10 週：Agent 4 建立 + 據點隔離
第 11-14 週：QC 串接 + 對帳模組

【Phase 3：AI 深化（8-12 週）】
目標：預測性採購 + 供應商評分自動化
範圍：Agent 5（發票自動化）+ 預測模組
成功指標：發票自動通過率 > 85%
```
