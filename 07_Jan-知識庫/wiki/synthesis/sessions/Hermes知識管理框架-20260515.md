# Hermes 知識管理框架

> 蒸餾自 Jan 的對話摘要 | 2026-05-15

## 框架全景圖

Hermes 的知識管理核心是將其定義為一個**具備「自我進化」能力的長期代理系統**，而非單次任務工具。分為五個面向：

| # | 面向 | 關鍵詞 | 核心價值 |
|---|------|--------|----------|
| 1 | 自學習閉環 | 技能卡、程序性記憶 | 經驗 → 技能 |
| 2 | 四層記憶架構 | 情境/持久/長期檢索/辯證建模 | 數位雙生 |
| 3 | LM Wiki 有狀態編輯 | 三層結構、數據飛輪 | 對話 → 事實 |
| 4 | Obsidian 視覺化 | Graph View、Markdown 標準 | 知識網絡 |
| 5 | 主動式上下文管理 | 40-60% 規則、Compaction | 防止 Context Rot |

## 五大面向詳解

### 1. 自學習閉環與技能累積

- **觸發條件**：任務涉及 ≥5 次工具呼叫
- **輸出格式**：Markdown 技能卡 → `~/.heremes/skills/`
- **更新機制**：使用中持續優化，遇更好方案即修補
- **標準**：遵循 `agentskills.io` 開放標準，可跨框架共享

### 2. 四層記憶架構

| 層級 | 內容 | 存儲位置 |
|------|------|----------|
| 情境記憶 (Episodic) | 每次任務的步驟、成敗原因、教訓 | daily notes |
| 持久記憶 (Persistent) | 環境事實、課程 | MEMORY.md |
| 使用者模型 | 偏好、溝通風格 | USER.md |
| 長期檢索 | 跨 Session 召回 | SQLite FTS5 + session_search |
| 辯證建模 | Honcho — 動態修正「你是誰」 | 內建模塊 |

### 3. LM Wiki 三層結構

```
不可變層 (Source)
    ↓ 蒸餾
Wiki 頁面層 (Pages) ← 為 Agent 打造，含摘要與實體索引
    ↓ 演化
協同進化層 (Schema) ← 人機共創
```

**數據飛輪**：傳統 RAG 每次從零開始；LM Wiki 將有價值答案歸檔回 Wiki，實現知識複利。

### 4. Obsidian 視覺化

- 所有內容為標準 Markdown
- Graph View 可視化知識點之間的邏輯連結
- 適合檢視跨領域的複雜關係（如不同論文間的引用脈絡）

### 5. 主動式上下文管理

- **40-60% 規則**：上下文使用率 >60% 即觸發自動壓縮
- **Compaction**：將對話蒸餾為核心事實
- **Re-Injection**：壓縮後重新注入核心規則（SOUL.md、AGENTS.md），防遺忘

## 與「結構化記憶系統」的關係

Hermes 框架側重 **Agent 自身的能力進化**；結構化記憶系統側重 **決策脈絡的保存與導航**。

兩者共同指向一個目標：
> 讓 AI 成為一個**記得你決策路徑、理解你判斷標準的穩定數位協作者**
